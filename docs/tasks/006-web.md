# 006 – apps/web (Next.js 15, app router)

Reference: ADR 0002 (UI v packages), ADR 0010 (importy: relativní cesty, žádný alias – ověř, jak Next kompiluje soubory mimo `apps/web`; `transpilePackages` je pro balíčky z node_modules, tady se nepoužije); engineering.md §3; frontend: použij skill `frontend-design` pokud je dostupný, jinak čisté, klidné UI – nic „AI-glow".

## Cíl

Shell aplikace, do kterého features montují své stránky. Přihlášení, výběr SVJ, inbox approvals, stránka pro podepsaný odkaz.

## Rozsah

1. Next 15, Tailwind, `packages/shared/ui` základní komponenty (Button, Card, Table, Badge, Dialog, Form pole nad react-hook-form + zod). Bez externí UI knihovny kromě Radix primitives (ADR pokud chceš jinak).
2. Auth: server actions volají API (`/auth/login`), cookie proxy; `getSession()` v server components; middleware přesměruje nepřihlášené.
3. Layout: levý panel (Přehled, Schvalování, Dokumenty, Revize, Úkoly, Vlastníci, Finance, Nastavení – položky se registrují z features přes `index.ts → navigation`), horní SVJ switcher (`svjId` v URL prefixu `/s/[svjId]/...`), přepínač na cross-SVJ pohled pro roli `manager`/`tenant_admin`.
4. Stránky v `app/`: jednořádkové re-exporty z features; kernel stránky: `/login`, `/s/[svjId]/approvals` (inbox: seznam, detail s evidencí a tlačítky), `/a/[token]` (náhled + POST rozhodnutí), `/settings/api-tokens` (vytvoření tokenu s checklistem toolů, seznam, revokace).
5. Datový přístup z UI: pouze přes API (fetch s cookie) – `ui/` nesmí importovat service (depcruise pravidlo `ui-no-service`).
6. Playwright smoke test: login → inbox → schválení approval → stav změněn.

## Akceptační kritéria

- `pnpm build` web bez chyb; `*.client.tsx` konvence lintem zelená.
- Playwright smoke prochází proti docker compose stacku.
- Stránka `/a/[token]` při GET nic nemění (ověřeno testem: stav approval po GET stejný).
